# Implementation knowledge

- User validation 2026-09-28: physical MIDI and gamepad CW practice input work well; user likes 600 Hz sidetone and reports useful detection with imperfect keying. Joined BK exposed the six-element decoder limit. Shared live/practice CwDecoder now supports nine-element groups and explicit prosign labels, including BK/SOS/HH. AR and BT take precedence over indistinguishable +/= patterns. HH is displayed, not interpreted as destructive editing. Noisy overflow remains unknown. See docs/cw-decoding.md; off-air performance is still separate from practice validation.

- CW practice: header window is independent of radio mode/source. `sdr-dsp::keyer` provides Straight/IambicA/IambicB sample timing, element memory, B squeeze tail, cancel, and sidetone. A new independent tap after A squeeze release must survive (regression test). `sdr-app::practice` has a 48 kHz worker, bounded timestamped GUI/MIDI contacts, separate input-source aggregation, 300 ms heartbeat, and pre-volume Morse feedback. MIDI optional `midi` feature (included by desktop), midir note/CC parser and stable port-ID monitoring; Bevy gilrs enabled for GUI controllers. Bindings/settings session-local. Practice input runs before egui BeginPass; capture presses but pass release events to avoid stuck UI states. GUI smoke needs a layout-settling frame/delay after learned labels change widths. See docs/cw-practice.md. 63 tests and practice GUI smoke passed; Arturia MicroLab connection opened, actual MIDI key/controller actuation still requires manual verification.

- CW 2026-09-27: Mode::Cw, 200/500/1000 Hz filters at 6 kHz, fixed 600 Hz BFO, 48 kHz pre-AGC/squelch power tap. Engine owns CwDecoder with optional CwConfig and cw_reset epoch; decoder-only revisions preserve audio/capture. Settings carry seed WPM, adapt, manual threshold, word-spacing multiplier. GUI Signal Data dispatches CW/RDS independently; bounded text also appears above spectrum. CSV mode is cw; decoder controls remain session-local. Research considered cwdit-morse, morse-codec, ditdah, ggmorse; no third-party decoder added/copied. See docs/cw-decoding.md for limitations and generated target/cw-demo.cf32. 55 tests, all-feature Clippy, core/DSP WASM, and CW GUI smoke passed; actual hand-keyed RF remains unvalidated.

- Memories/scanning: CSV storage (not JSON), minimum columns name/frequency_hz/mode, optional group defaults to filename, optional full receiver fields and scan_enabled. Default user library memories.csv, override RUSTSDR_MEMORY_FILE; explicit save required. Scan state machine runs in native worker, not Bevy. Channel power is pre-audio for every mode. Fixed hold ignores continued signal; StopScan targets the active revision and preserves actual tuned settings and scan position without a receiver reset. Autoscan retains command revision; scan visit and audio discontinuity identify subsequent visits. UI uses virtual rows and asynchronous file tasks. See docs/memories-and-scanning.md; local GUI and live scan probe artifacts are in target/memory-scan/.


- Architecture refactor: "sdr-app::engine::Engine" owns the worker; GUI uses "Client" commands/outputs. Compatibility "Controller" alias remains for probes. Native RTL/audio/GUI features are independent; use "desktop" for the usual GUI with audio. Receiver audio subscriptions are pre-monitor but post-mode processing (not FM multiplex). Ordered streams report overflow; generations/sample positions accompany audio/spectrum. Mode settings persist within a session; compact controls use a floating window. See docs/engine-boundary.md. Core/DSP WASM check passed locally; Linux/macOS CI is configured but unexecuted. Matched development traces and artifacts: docs/architecture-trace-comparison.md, target/architecture-baseline/. Existing user trace preserved.


- Optional `sdr-app/perfetto` feature includes GUI and Bevy Chrome tracing. `TRACE_CHROME` selects the JSON destination; keep spans enabled via `RUST_LOG=info,wgpu=error,naga=warn`. Normal close flushes the trace. Custom `sdr.*` block-level spans cover controller/DSP/audio preparation/UI; waits are labeled separately and the audio callback remains uninstrumented. `warn,sdr_app=info` produces a smaller application-only trace. See docs/profiling.md for release capture instructions; headless CLI does not initialize a tracing subscriber.

- UI: interface/mode/VFO controls are in the header; Diagnostics button or F12 opens a separate metrics window. Errors stay visible in the header. Bevy sysinfo diagnostics use normalized process CPU and GiB process memory; GPU pass timings are partial instrumented work, not utilization. Start Controller during Bevy Startup after renderer initialization so short files do not finish during graphics startup. GUI smoke now exercises Diagnostics open/close and checks live FPS/CPU values.

- Voice modes use `sdr_dsp::ReceiverConfig` / `Receiver`, 2.4 MS/s IQ in and 48 kHz `StereoFrame` out. GUI `--mode` values: wfm, stereo, am, nfm, usb, lsb. Mode changes retain capture, waterfall, and audio endpoint; they reset DSP and invalidate queued audio. Normal RTL range is 28.8–1700 MHz; HF direct sampling is not enabled. See README for per-mode fixtures and docs/mode-backlog.md for future decoder boundaries. 29 integration tests and a stereo file GUI smoke passed; the 106.7 MHz stereo live probe acquired pilot lock with zero reported losses. The user subsequently completed a 30-minute manual multi-mode stability test and validated most modes. AM remains outstanding; no instrumented memory/loss record or exact mode list was supplied. Next design: modular controls/results and RDS/RBDS, with HD Radio a separate IQ decoder; see docs/receiver-panels.md. External converter model/translation is unknown.

- Synthetic block leases recycle to their originating generation. Outstanding leases exhaust that generation's fixed pool and backpressure production; stop must remain cancellable in that condition. The public session restart test covers this behavior.

- RTL-SDR live FM is implemented. See docs/implementation-status.md and third-party/README.md. The top-level user DLL is x86; the separate RTL-SDR Blog V1.4.0 x64 runtime is selected first. Device 0 at 2.4 MS/s, 28 dB gain; station plus 250 kHz capture center. Preserve the original DLL.

- IQ file playback uses explicit center/rate and cf32le at 2.4 MS/s; it shares multi-mode receiver/FFT processing with RTL. EOF and faults are separate states. New failures must clear old EOF/progress. Tests cover paced replay and recovery. Partial final FFT windows are omitted; all valid IQ still enters demodulation. See README for the generated fixture and smoke command.

- Tuning now separates VFO from capture center. Hot revisions preserve the active source and audio endpoint; run_live updates its settings revision and run_worker must retain that returned revision to avoid reopening. RTL retune joins USB reads before changing native frequency. Waterfall rows retain original RF centers. File VFO tuning must not rewind playback. Retune discards are intentional and distinct from IQ overflow.
- RDS/RBDS (2026-09-25): Receiver::process_with_multiplex taps pre-audio 240 kHz WFM; engine runs bounded Rust RdsDecoder, exposes coalesced Update.rds with enclosing station/revision identity. Decoder-only settings preserve audio epochs and scan pause (same Arc plan identity); RF/mode/gap changes reset decoder. FM data header window is separate from voice controls. Live 89.9 MHz decoded KCRW PI 1718 and RadioText, 207 groups/20s, zero IQ drops; 106.7 probe had no groups. See docs/fm-broadcast-data.md for limits, fixture, smoke and probe. Extended charset, regional PTY labels and further services remain backlog.

- VOR needs wide AM envelope/channel IQ; ordinary AM voice filtering removes the 9960 Hz reference. Reference modulation alone plus noise must not produce a radial. The regression corpus pins KLO/ARL ranges and rejects missing direct AM modulation.

- rs-rtl 0.5.0 AsyncReadHandle Drop joins before dropping its bounded receiver. Stop and drain to End before dropping to avoid full-queue deadlock. Use stop/join plus synchronous set_center_freq rather than unacknowledged streaming tune commands. Its read_gain returns an encoded register value; do not label it as measured dB.
