# IC-705 USB reception and transmit test

Select **IC-705 USB** in Interface (included by `desktop`, or enable `ic705`). The radio performs demodulation. RustSDR captures 48 kHz mono/stereo AF audio, supplies the existing FT decoder subscriptions, and displays the audio spectrum/waterfall. CI-V controls frequency, mode and DATA mode; front-panel changes are read back. This is not yet a wideband RF/IQ or CI-V bandscope display.

## Connected Windows setup

Detected on 2026-10-03:

- CI-V USB A: **COM19**, 19200 baud, address **A4** (164 decimal in the UI). COM20 is the second serial interface and is not used.
- Radio input: **Microphone (USB Audio CODEC )**, 48 kHz mono float32.
- Radio transmit output: **Speakers (USB Audio CODEC )**. Select this explicitly while stopped.
- Monitor output: choose headphones or speakers attached to the computer. The tested endpoint was **Headphones (ROG CETRA TRUE WIRELESS SPEEDNOVA)**.

Device names/ports may change. Refresh devices and select the exact endpoints. Ambiguous names are rejected. Known radio-codec outputs are blocked from ordinary monitoring, including when Windows makes the radio its default playback device. Windows' other applications are outside this routing protection.

Set the radio's USB AF/IF output to **AF**. A new connection adopts the radio's current dial/mode; it does not replay old tuning or TX commands. Connection/audio choices and tuning step persist under `devices.ic705`; reception and transmit actions do not resume automatically. Disconnects require Start Reception after reconnecting.

On Windows, radio AF capture requests **WASAPI RAW** for this stream, bypassing microphone-processing effects without changing system settings. Ordinary microphone processing was found to suppress this IC-705's receive audio: normal capture measured about -110 dBFS, while RAW measured -31 dBFS. The corrected engine also measured about -31 dBFS with zero input drops. The controls show a USB input-level readout. RAW startup failures are reported explicitly rather than silently reverting to processed audio. QMX uses the same capture adapter; non-Windows capture remains on CPAL.

```powershell
cargo run -p sdr-app --features desktop -- --gui --ic705 COM19 --radio-input "Microphone (USB Audio CODEC )" --monitor-output "Headphones (ROG CETRA TRUE WIRELESS SPEEDNOVA)"
```

## Initial transmit capability

The output path currently generates a **three-second, 1 kHz USB audio test tone**. Microphone transmission, CW keying and FT encoding are follow-ups. To test, use the intended dummy-load frequency, select USB or LSB with DATA enabled, simplex (split/duplex off), and set the radio's **Connectors > MOD Input > DATA MOD** to **USB**. USB SEND/keying may remain off; CI-V supplies PTT. The app checks modulation routing and RX/TX dial agreement before keying.

Select the radio transmit endpoint, set RF power (0–10% for this initial test), confirm the dummy load, then click **Send 3-second test tone**. **0% is the radio's minimum setting, not zero RF power**. Percentage is not calibrated watts; actual output depends on the radio, supply, modulation level and external measurement. The test temporarily lowers RF power and restores its previous setting after confirming RX. Test audio has a fixed low level independent of listening volume.

Stop test TX, Stop reception, interface changes and orderly shutdown end an app-owned test. A lost keying acknowledgement still triggers an RX attempt. Audio generation also has a three-second sample budget. Serial deadlines bound normal error handling, but an unplugged USB cable or terminated process cannot guarantee delivery of an unkey command: release TX on the radio if necessary. Automatic repeat/reconnect TX is not implemented.

The receive-audio watchdog tolerates missing audio while CAT reports TX and grants a fresh two-second timeout when CAT confirms RX. This prevents a receive-audio pause during the three-second test from being treated as a disconnected input. Capture failures and CAT errors still stop the session; CI-V errors include the command bytes to help distinguish serial failures from receive-audio timeouts. Automated tests cover TX silence, audio recovery and failure to resume.

PTT-off acknowledgement can precede the radio's actual RX status. The driver polls for RX at 25 ms intervals with a 750 ms transition deadline (each CI-V exchange also has its own bounded timeout), and restores power only after RX is confirmed. A live dummy-load test at 7.170 MHz reproduced the old immediate `Radio still transmitting` failure. After the change, the production-engine probe reported TX at 1.471 seconds, RX at 4.562 seconds and successful spectrum recovery without ending the session. Tests also verify that failure to confirm RX retains reduced power and cleanup ownership.

The opt-in `ic705_tx_probe` example runs one three-second tone at minimum radio power and verifies TX-to-RX spectrum recovery. It requires explicit port, audio endpoints, expected dial in Hz and `--dummy-load-test`; it never tunes the radio. Unlike the receive probes below, this example transmits RF.

## Validation and reproducible probes

CI-V identification, connector reads, +100 Hz tuning/readback, USB DATA mode selection, and restoration to the original 146.520 MHz FM state passed on the connected radio. The initial five-second engine run delivered 222,240 subscribed audio frames and 54 spectrum frames with zero reported input drops, but its extremely low audio level was subsequently traced to Windows processing, not established as a dummy-load effect. A live GUI smoke displayed reception and captured `target/ic705-receive.png`. After the RAW fix, the receive probe at 7.055 MHz USB delivered 223,200 subscribed frames and 54 spectrum frames, with RMS 0.0293 and zero reported input drops.

No live TX was performed during initial integration: test frequency, maximum power and dummy-load rating are awaiting user specification. Protocol tests cover key/unkey, power restoration, dropped-session cleanup, lost TX acknowledgement, route/frequency/power rejection, BCD errors and DATA-off framing. These do not measure emitted RF or prove hardware disconnect behavior during TX.

```powershell
# Read-only radio identification/configuration and TX preflight (never keys)
cargo run -p sdr-devices --features cat --example ic705_probe -- COM19
# Optional reversible tune/mode roundtrip; never keys
cargo run -p sdr-devices --features cat --example ic705_probe -- COM19 19200 --tune
# List exact audio endpoint labels
cargo run -p sdr-app --features ic705 --example ic705_receive_probe
# Five seconds of receive audio; monitor is muted, no TX
cargo run -p sdr-app --features ic705 --example ic705_receive_probe -- COM19 "Microphone (USB Audio CODEC )" "Headphones (ROG CETRA TRUE WIRELESS SPEEDNOVA)"
# With an audible signal on the radio, require usable input level as well
cargo run -p sdr-app --features ic705 --example ic705_receive_probe -- COM19 "Microphone (USB Audio CODEC )" "Speakers (BEHRINGER UMC202HD 192k)" --min-dbfs -80
```

The read-only TX preflight also identifies the specific blocked condition. During follow-up testing, the connected radio was correctly in USB DATA at 7.170 MHz, but DATA MOD selected MIC. Enabling DATA mode does not select USB modulation automatically: set **MENU > SET > Connectors > MOD Input > DATA MOD > USB** on the radio. The app now reports that setting explicitly, separately from mode, DATA, split and frequency errors. A regression test verifies that this rejection sends neither PTT-on nor an RF-power change; no live transmission was performed for this diagnosis.

The GUI command above accepts `--ic705-smoke` for an automatic receive-only screenshot and exit without reading/writing preferences. Native serial and audio dependencies remain feature-gated; hardware-free builds still compile.

The CI-V transport is pure Rust over `serialport`; device enumeration/playback uses CPAL, with a Windows-only WASAPI RAW adapter for radio capture. Hamlib is not needed for this bounded IC-705 adapter. Broader radio coverage may warrant a Hamlib adapter behind the same engine boundary. Scope data, band-stack controls, IF capture, microphone/encoded TX, radio-side timeout configuration and stronger TX-loss handling remain follow-ups.

Protocol reference: [Icom IC-705 CI-V reference guide](https://www.icomeurope.com/wp-content/uploads/2020/08/IC-705_ENG_CI-V_1_20200721.pdf).

Capture reference: [Microsoft audio client properties](https://learn.microsoft.com/en-us/windows/win32/api/audioclient/ns-audioclient-audioclientproperties-r1). The adapter sets RAW before initialization, validates float sample format, handles silent packets and discontinuities, and stops capture before releasing its COM apartment.
